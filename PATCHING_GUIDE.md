# KOR-ETERNAL FRONTIER — Beginner Patching Guide

You can change the starter scenario's main balance values without editing C#.

## Project files

- `Program.cs` starts SDL3, Gondwana, input polling, and the fixed-step update loop.
- `Campaign/` contains deterministic world generation, campaign rules, save validation, and battle transition data.
- `Simulation/OutpostSimulation.cs` contains the worker, economy, construction, objective, and Blight rules.
- `Simulation/ScenarioBalance.cs` validates editable balance values.
- `Rendering/CampaignRenderer.cs` draws the title menu and strategic map; `Rendering/OutpostRenderer.cs` draws the tactical map and HUD. Drawing code does not control the simulation.
- `Assets/Art/` contains the game's custom raster images. `Tools/generate_art.py` rebuilds them using Python and Pillow; it uses original procedural artwork and downloads no game art. On Arch Linux, install the generator dependency with `sudo pacman -S python-pillow`, then run `python Tools/generate_art.py` in this folder. The PNGs are copied into both development and release builds.
- `Assets/Metadata/art_manifest.json` registers each PNG, its category, source dimensions, recommended anchor, authored view, and animation timing. `Rendering/Artwork.cs` checks registration and dimensions when images are loaded. `Tools/asset_tools.py --write-manifest --contact-sheet` refreshes metadata and creates `Assets/Previews/contact-sheet.png`; `python Tools/asset_tools.py` validates registration, readable images, metadata, and dimensions.
- `Data/Balance/scenario.json` contains the starter scenario's editable costs, rates, and starting resources.
- `Tests/ScenarioChecks.cs` and `Tests/CampaignChecks.cs` contain dependency-free gameplay checks invoked by `--self-test`.
- `artifacts/linux-x64/` is generated by the Linux packaging script and is excluded from Git.

## Art assets

The battlefield uses 54x27 world-space diamond tiles (2:1 isometric). Ground tile images are 256x128 and are drawn centered on the tile; actor and building images use explicit destination rectangles in `OutpostRenderer`, with visual ground contact near the lower edge. Campaign map art uses a separate strategic-map layout. Shared palette and projection notes are in the manifest.

To change artwork, edit `Tools/generate_art.py` and run `python Tools/generate_art.py`. Source geometry and material choices live in that script; generated PNGs are the runtime files under `Assets/Art/`. Run `python Tools/asset_tools.py --write-manifest --contact-sheet` after changing dimensions or adding images, then inspect the contact sheet and run `python Tools/asset_tools.py` to validate. After a build, run `dotnet run --project GondwanaGame.csproj --configuration Release -- --verify-art` to decode every registered image with the game's Skia renderer. Keep each PNG name stem equal to its stable `assetId`; the renderer requests those IDs. Do not rename an existing ID unless all renderer references and the manifest are updated together.

The current units and buildings are authored as single southeast-facing illustrations. The manifest reserves an explicit eight-direction order for future directional sets, but the renderer does not rotate or mirror these asymmetric illustrations, and there are no multi-frame walk or attack sheets yet. Animation entries currently describe each image as a static idle frame. Source artwork is generated locally; no third-party art source or external graphics application is required.

## Change balance values

Open `Data/Balance/scenario.json` in a text editor. Keep the JSON commas and quotation marks intact.

For example, to start with more alloy and reduce purifier cost, change:

```json
"startingAlloy": 140,
"purifierAlloyCost": 80
```

to:

```json
"startingAlloy": 220,
"purifierAlloyCost": 65
```

Other useful values:

- `startingSupplies`, `suppliesPerGather`: supply economy.
- `alloyPerGather`: alloy gained at the western salvage deposit.
- `workerSpeed`: worker movement in tiles per second.
- `workIntervalSeconds`: time between gathering and construction work.
- `purifierSuppliesCost`, `purifierWorkPerInterval`: purifier construction.
- `blightSpreadSeconds`, `blightSpreadSkipEvery`: Blight spread cadence and density.
- `purifierRange`: how far completed purifiers cleanse.
- `shelterDamagePerSecond`: damage while the command shelter is infected.

The game checks values at startup and explains invalid values. Restore the original scenario values by reversing only your intended JSON edits in your text editor.

Starting map dimensions, fixed deposit and rock locations, the tactical objective, and visual colors are currently defined in C# (`OutpostSimulation.cs` and `OutpostRenderer.cs`). Campaign outpost costs, regional yields, Ward Protocol, turn production, and the seeded map are in `Campaign/CampaignSimulation.cs`. The campaign currently has one functional technology and one army; it does not yet have diplomacy, rival AI, or tactical production queues.

## Campaign balance changes

Campaign values are currently source constants and need a rebuild:

- Outpost and upgrade costs: `CanDevelopSelected` and `DevelopSelected`.
- Ward Protocol cost and tactical damage: `CanResearchWard`, `ResearchWard`, and `TacticalGuardianDamage`.
- Baseline production, terrain yields, army upkeep, and readiness: `RegionYields` and `EndTurn`.
- Blight spread interval and containment: `EndTurn` and `SpreadBlightOneRegion`.
- Map topology and starting conditions: `WorldGenerationService`.

The content system is only partly data-driven. Tactical costs and worker rates are in `Data/Balance/scenario.json`; there is no JSON unit/building/technology catalog yet. Make one small edit, then run the build and `--self-test` commands below.

Campaign saves are stored at `${XDG_DATA_HOME:-~/.local/share}/kor-eternal-frontier/campaign.json`. Copy the file before editing it manually. Settings persistence is not implemented.

## Build, test, and package

Install the .NET 8 SDK and SDL3 on NyarchLinux/Arch Linux. From this folder:

```sh
dotnet build GondwanaGame.csproj --configuration Release
dotnet run --project GondwanaGame.csproj --configuration Release -- --self-test
./build-linux.sh
./launch-kor.sh
```

The self-test does not need a window. The published executable and its native Skia file are placed under `artifacts/linux-x64/`. `launch-kor.sh` can be double-clicked in many file managers after marking scripts executable, or launched from a terminal.

## Recover from a broken edit

Before editing, make a copy of the file you plan to change. If you use Git and want to discard only your own edits to one tracked file, review them first with `git diff -- path/to/file`, then use `git restore -- path/to/file`. Do not run that command on files containing someone else's changes. To get back to the last packaged state, rerun `./build-linux.sh` after the build succeeds.

If the game exits, start it from a terminal so the error is visible. Configuration errors name the JSON path; SDL startup errors describe the missing video/runtime dependency. The game does not currently write a persistent log file. Invalid or unsupported campaign saves are rejected rather than silently reset.

## Asking an AI assistant for a focused patch

Name one feature and its file boundary. For example: “In `Simulation/OutpostSimulation.cs`, increase the worker's gather rate using the existing `Data/Balance/scenario.json` setting. Preserve the other gameplay rules, run the Release build and `--self-test`, and report the files changed.” Ask for a focused diff and verification rather than a rewrite of the whole project.
